# Oil Engineer Report Fixer

Веб-приложение для инженеров ГРП: загрузка Excel-отчётов с операций, разбор листов
`Замес 1 Заказчику` и `Анализатор`, визуализация графиков и предпросмотр корректировок.

## Назначение

Инструмент помогает инженеру:

- загрузить «сырой» Excel-отчёт по операции ГРП (дата, номер операции, скважина);
- автоматически разобрать ключевые листы (`Замес 1 Заказчику`, `Анализатор`);
- посмотреть исходные графики каналов и предложенные корректировки;
- скачать «исправленную» версию отчёта.

> **Важно:** корректировки **не применяются автоматически**. В UI всегда показывается
> исходный и предложенный вариант — финальное решение остаётся за инженером.
> На текущем этапе бизнес-логика ещё не реализована, это только скелет проекта.

## Стек

- **Backend:** Python 3.11, FastAPI, SQLAlchemy, pandas, openpyxl
- **Frontend:** Vanilla JS + [Plotly.js](https://plotly.com/javascript/)
- **БД (метаданные сессий):** PostgreSQL 16
- **Инфраструктура:** Docker Compose (`backend`, `frontend`, `postgres`)

Сырые загруженные Excel-файлы хранятся во временном хранилище сессии (на томе
backend-контейнера) и удаляются после закрытия сессии. В БД лежат только
метаданные (дата операции, номер, скважина, статус и т.п.).

## Быстрый старт

Требуется Docker и Docker Compose.

```bash
cp .env.example .env
docker compose up --build
```

После сборки:

- Frontend: <http://localhost:8080>
- Backend (FastAPI docs): <http://localhost:8000/docs>
- Healthcheck: <http://localhost:8000/health>
- PostgreSQL: `localhost:5432`

Остановить и удалить тома:

```bash
docker compose down -v
```

## Текущий статус

Реализован только **первичный скелет**:

- структура backend/frontend;
- FastAPI с `/health` и заглушками роутеров `sessions`, `upload`, `charts`;
- модель метаданных сессии в БД;
- статический фронтенд с формой и контейнерами для графиков;
- nginx-прокси `/api` → backend.

Бизнес-логика разбора Excel и построения графиков **ещё не реализована**.

## Планируемый MVP-поток

1. Инженер открывает UI, вводит дату операции, номер операции, имя скважины.
2. Загружает Excel-отчёт операции → создаётся сессия (метаданные в Postgres,
   файл во временном хранилище backend).
3. Backend парсит листы `Замес 1 Заказчику` и `Анализатор` (pandas/openpyxl),
   применяет правила из `channel_criteria.yaml`.
4. Frontend через Plotly.js рисует:
   - исходные графики каналов;
   - предлагаемые корректировки (предпросмотр, **без автоприменения**).
5. Инженер подтверждает/отклоняет правки и скачивает итоговый файл.
6. После закрытия сессии временные файлы и связанные данные очищаются.
